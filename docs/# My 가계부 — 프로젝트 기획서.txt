# My 가계부 — 프로젝트 기획서

## 1. 개요
- **프로젝트명**: My 가계부
- **목적**: 커플/개인용 가계부 웹앱. 수입·지출·저축목표를 한눈에 보고 관리
- **기술 스택**: Plain HTML / CSS / JS (프레임워크 없음)
- **기준 디자인**: 업로드한 목업 이미지 (`가게부모양.jpg`)

## 2. 폴더 구조 (확장자별 하위 폴더)
```
my-budget-app/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── main.js
├── assets/
│   └── (이미지, 아이콘 등)
└── docs/
    └── 기획서.md
```
추후 페이지가 늘어나면 `income.html`, `expense.html`, `stats.html`, `settings.html`을 루트에 추가하고,
공통 CSS/JS는 `css/`, `js/`에서 계속 공유하는 구조로 확장합니다.

## 3. 목업 이미지 분석 — 홈 화면(index.html) 구성요소

### 3-1. 상단 네비게이션
- 좌측: 로고(아이콘 + "My 가계부")
- 중앙: 메뉴 — 홈 / 수입 / 지출 / 통계 / 설정 (홈이 현재 활성 상태, 언더라인 표시)
- 우측: 사용자 아바타 아이콘 + "안녕하세요, 사용자님" + 드롭다운 화살표

### 3-2. 히어로 배너
- 우측에 인물 사진 배치, 좌측은 밝은 배경 + 텍스트
- 카피: "오늘도 현명한 선택," / "알뜰한 가계부로 시작하세요!" (강조) / "수입과 지출을 관리하고 목표를 달성해보세요." (서브텍스트)
- 사진은 배경과 자연스럽게 블렌딩되는 톤

### 3-3. 요약 카드 (히어로 하단에 겹쳐지는 흰색 박스)
4개 항목이 원형 아이콘 + 라벨 + 금액으로 구성, 세로 구분선으로 분리:
| 아이콘 | 라벨 | 값 | 색상 |
|---|---|---|---|
| 💰 파란 원 | 이번 달 총 수입 | 3,850,000원 | 파랑 (수입) |
| 📕 빨간 원 | 이번 달 총 지출 | 2,450,000원 | 빨강 (지출) |
| 📊 초록 원 | 이번 달 잔액 | 1,400,000원 | 초록/중립 |
| 🎯 보라 원 | 저축 목표 달성률 | 65% | 보라 (브랜드) |

### 3-4. 거래 내역 테이블 (좌우 2단)
**좌: 수입 내역**
- 헤더: "↓ 수입 내역" + 우측 "+ 수입 추가" 버튼(파란 테두리)
- 컬럼: 날짜 / 항목 / 금액(+파란색) / 메모
- 하단: "더보기 >" 링크

**우: 지출 내역**
- 헤더: "↑ 지출 내역" + 우측 "+ 지출 추가" 버튼(빨간 테두리)
- 컬럼: 날짜 / 항목 / 금액(-빨간색) / 메모
- 하단: "더보기 >" 링크

## 4. 컬러 & 타이포그래피 제안
- **브랜드/포인트**: 보라 `#7C6FF0`
- **수입**: 파랑 `#4C7EF3`
- **지출**: 빨강 `#F45B5B`
- **잔액/중립 강조**: 그린 계열 (예: `#3FB88E`)
- **배경**: 오프화이트 `#FAFAFB`
- **폰트**: 제목/포인트 — Gowun Dodum (한글 감성 서체), 본문/UI — Pretendard (가독성 좋은 UI 서체), Google Fonts / jsDelivr CDN으로 로드

## 5. 데이터 모델 (추후 상세화 예정)
- `users` — 사용자 정보 (커플 공유 계정 고려)
- `categories` — 수입/지출 카테고리
- `incomes` — 수입 내역 (날짜, 항목, 금액, 메모)
- `expenses` — 지출 내역 (날짜, 항목, 금액, 메모)
- `goals` — 저축 목표

> 지금 단계는 정적 목업(더미 데이터)으로 화면을 완성하고, 이후 단계에서 로컬스토리지 → 백엔드 순으로 데이터 계층을 붙이는 것을 권장합니다.

## 6. 개발 로드맵
1. **[현재] 기획 & 폴더 구조 확정**
2. 홈 화면(`index.html`) 정적 퍼블리싱 — 네비, 히어로, 요약 카드, 수입/지출 테이블
3. 반응형 처리 (모바일: 테이블 가로 스크롤, 요약 카드 스택)
4. 수입/지출 추가 UI (모달 또는 별도 페이지) — 더미 데이터 기반 상호작용
5. 수입/지출/통계/설정 페이지 뼈대 추가
6. 로컬스토리지 기반 데이터 저장 → 실제 CRUD 동작
7. (선택) 백엔드 연동 / DB 설계 반영
